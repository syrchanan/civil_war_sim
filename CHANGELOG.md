# Changelog

All notable changes to this project are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).
Nothing has been released yet: everything up to the first public site is 0.1.0-alpha.

## [Unreleased]

Working towards 0.1.0-alpha, the first site. Design decisions and status live in `docs/ROADMAP.md`.

### Added
- Phase A, the Python engine:
  - Seeded RNG (xoshiro128\*\*) and fdlibm `log` / `exp`, bit-identical to JavaScript.
  - Morale budget model with break points from experience and morale; game time in minutes.
  - Round engine for any number of units per side: per-unit orders (ranged / melee / idle), melee contact,
    charges with closing fire and a contact test, rout prisoners, captured guns, and casualty settlement
    (killed, wounded, walking wounded, captured, returned).
  - Unit-type matchups (infantry, cavalry, artillery and subtypes), per-gun artillery with ammo choice.
  - Battle state file (JSON) with exact resume; setup and scenario files; step API (`imperial_generals.api`)
    and CLI (`python -m imperial_generals`).
  - Tuning harness: seed batches, matchup grids and plots, calibration scenarios.
  - Player validation scenarios: an `expect` block, `check` grading and reports, player spreadsheets.
- Broken units are harder to hit: fire ×0.5 and melee pursuit ×0.75 (placeholders).
- `on_break` in orders: fire keeps on a broken target or switches to the strongest / weakest enemy; melee
  falls back or pursues. Switches are reported as `retargets`.
- The field holder is decided by three votes (casualty exchange, routs, strength standing) when both armies
  still stand; the side summary reads it as won / lost / drawn, and the result records how it was decided.
- Phase B, the TypeScript port in `web/` (Vite + Vitest): RNG, fdlibm, params, morale, units, the round engine
  and the state file, matching the Python engine exactly on shared parity fixtures (`test_cases/parity/`,
  generated by `python -m imperial_generals.parity`).
- The browser client (`web/`, Preact): build armies, give orders with a live preview, fight rounds, strength charts,
  finish with the field votes, download and open battles; a map of the field (units as blocks, orders as arrows,
  drag to place or move units; display only).
- Order of battle and side summary in the TypeScript port.
- `scenario-from-state` (CLI and `api.scenario_from_state`): a saved battle, e.g. downloaded from the site, becomes
  a scenario that replays it exactly and can be rerun over other seeds or parameters.
- Player mode: the site opens in a player view (`?mode=admin` for admins); players command one side, estimate the
  next round over 200 runs (typical outcome and an 8-in-10 range), and download an orders file for the admin, who
  loads players' files (as does Python's `resolve --orders`).
- The richer map: units face a way (rotated blocks, front edge marked; Q / E or a handle to turn them; `facing` on
  positions, compass degrees, saved in state and orders files); every round records where units stood as it began
  (`positions` in the round history, both engines), so any round can be replayed on the map; click a unit, then an
  enemy, and confirm fire or charge (only what the unit can do) to give it that target.
- Deploys to GitHub Pages (https://syrchanan.github.io/civil_war_sim/) after CI passes on main.
- `CHANGELOG.md`, `python/requirements.txt`, CI (Python and TypeScript tests, both with 100% coverage, and a web
  typecheck).

### Removed
- The stale v0.2 TypeScript port (`typescript/`) and `run_tests.py`; the new port lives in `web/`.
